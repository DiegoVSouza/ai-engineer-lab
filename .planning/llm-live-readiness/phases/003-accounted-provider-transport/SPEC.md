# Phase 003 — Accounted provider transport

Expose the shared guard through a versioned JSON-lines subprocess protocol. A project campaign controls its own synthetic cases, prompts, graders and trial artifacts; the root Builder transport reads only numbered credentials and sends fixed-model Groq requests after authenticated catalog checks and durable per-project provider reservation. It imports no product source.

Only owning projects with an explicit synthetic-only execution manifest may initialize usage storage or dispatch. Foundation validation uses temporary project trees and simulated HTTP. No actual generation or production usage initialization occurs until an owning-project integration phase authorizes its paths.

Acceptance: count each attempt exactly once, bound full rendered request input and existing output caps, disable hidden retries, normalize feedback without raw headers/credential identities, retain unknown failed usage, stop on operational errors, validate observed model/usage and preserve accounting overruns. Raw synthetic response text exists only in the in-memory protocol, not campaign artifacts or logs. Human review/promotion remain pending.
